## 제목

- 핵심 질문이나 주장을 담는다. "월 DTO가 얼마를 넘으면 정액제가 유리한가 – AWS Direct Connect 정액 요금제(Flat-rate) 손익분기점 분석"처럼 질문 – 서비스명 구조가 잘 맞는다
- 제목 안의 en dash(–)는 허용한다(본문에서는 금지). 첫 등장 서비스 기능명은 "정액 요금제(Flat-rate)"처럼 한국어(English) 병기

- 초안 날짜는 작성일, 게시 시 게시일로 교체
- 공동 저자가 있으면 고객 저자 먼저, AWS 저자 다음

## 리드

- 헤딩 없이 제목·바이라인 아래 1~2문단
- 사용자 취향에 따라 질문형(2~3개) 또는 선언형으로 연다. 사용자가 질문 제거를 요청하면 마치며의 "글머리의 질문으로 돌아가겠습니다" 같은 연결 문장도 함께 제거한다
- 마지막에 **대상 독자와 선행 지식을 한 문장**으로: "이 글은 ~를 운영하는 네트워크 엔지니어와 FinOps 담당자를 대상으로 하며, ~의 기본 개념을 알고 있다면 무리 없이 읽을 수 있습니다."
- 계산이 있는 글은 기준(단가 확인일, 가상 청구서 기간, 시간 수)을 리드에서 한 문장으로 밝힌다

## 헤딩

- H2는 `## 1.`, `## 2.` 번호 매김. H3는 `### 1.1` 형식, 그 아래 깊이는 쓰지 않는다
- 헤딩은 명사구 또는 평서형. 혼잣말형("~할까") 금지, 콜론 부제("X: Y") 반복 금지
- 본문에서 섹션 번호를 하드참조하지 않는다("4쪽에 설명했습니다", "앞서 6.2에서" 금지). 내용으로 지칭한다
- 마지막 본문 섹션은 항상 "마치며". 리드의 질문에 답하는 수미상관으로 닫고, 마지막 문장은 "이 글의 계산식과 표가 여러분의 ~ 검토에 실질적인 참고가 되기를 바랍니다." 계열

## 표

- 표 먼저, 캡션은 표 **바로 아래** `*표 N. ...*`. 캡션에 단위·전제(USD, 세전, 시간 수, TB=1,024 GB)를 적는다
- 표 도입 문장은 표에 없는 정보만(전제, 산정 기준). 표 내용 요약 금지. 표 뒤에는 해석 문단
- 번호는 1부터 연속. 시나리오 표를 지우면 뒤 번호를 모두 당긴다
- 절감액 등 파생 수치는 합계 금액으로 계산(월별 비율 평균 금지). 음수는 `-517.40`처럼 하이픈, 의미는 캡션에 명시

## 그림

- 이미지 먼저, 캡션은 이미지 **바로 아래** `*그림 N. ...*`
- 이미지 경로는 `images/<slug>-figNN-<name>.png` 상대 경로
- alt 텍스트는 그림을 보지 못하는 독자에게 결론까지 전달하는 한 문장(축, 주요 값, 교차점 위치)
- 간략화한 요소는 캡션에서 밝힌다("회선 6개는 간략화해 표시했습니다")

## 계산식

코드 블록 한 개로 계산식을 보여준다. 마이너스는 하이픈, 나누기는 `÷`.

```
손익분기 DTO(GB) = (월 정액 요금 - 월 종량제 포트 비용) ÷ DTO 단가(USD/GB)
```
