# 공동 저자 원고

공동 저자가 있는 원고에서 따른다. 단독 원고라도 고객 저자나 서비스팀 리뷰어가 섹션을 맡으면 같은 규칙을 적용한다. (2026-11-01 추가, blog-writing 워크플로에서 이관)

## 시작할 때 합의할 것

| 항목 | 합의 내용 | 합의가 없을 때 |
|---|---|---|
| 섹션 분담 | @담당자가 표시된 개요가 있으면 그 구조를 그대로 따른다 | 사용자에게 분담을 묻고 작성을 시작하지 않는다 |
| 헤딩 번호 깊이 | 2단계(`## 1.`)인지 3단계(`### 1.1`)까지인지 | structure.md 기본값 |
| 코드 예시 스타일 | 공동 저자가 bash CLI를 쓰면 내 섹션도 bash | 문서 안에서 먼저 나온 스타일 |
| 용어 병기 | 첫 등장 병기 형태와 이후 표기 | style.md 확정 형태 |
| 바이라인 순서 | 고객 저자 먼저, AWS 저자 다음 | structure.md |

## 상대 섹션 피드백

- 상대 섹션은 직접 고치지 않는다. 코멘트 형식으로 전달한다: 원문 인용, 수정안, 한 줄 근거
- 위치는 섹션 번호 대신 Cmd+F로 찾을 수 있는 검색어로 안내한다
- 한 번 지적받은 패턴(번역투, 섹션 번호 하드참조 등)은 내 섹션 전체에 선제 적용하고, 상대 섹션에서 같은 패턴을 찾으면 코멘트 목록에 함께 넣는다

예:

```
[검색어] "앞서 6.2에서 설정한"
원문: 앞서 6.2에서 설정한 VPC 모드를 그대로 사용합니다.
수정안: 앞에서 VPC 모드로 배포한 Runtime을 그대로 사용합니다.
근거: 섹션 번호 참조는 순서를 바꾸면 어긋납니다(style.md).
```

## 협업 문서 도구로 옮긴 뒤 점검

Quip, Word, Google Docs 같은 협업 도구로 원고를 옮긴 뒤에는 붙여넣기 오류 여섯 가지를 문서 전체에서 점검한다.

1. 같은 문장이 두 번 들어감
2. 수정 전 구버전 문장이 남아 있음
3. 문단이 위 불릿 안으로 병합됨
4. URL이 `<https://...>` 꺾쇠로 감싸짐(마크다운 자동링크 잔재. 코드 블록 안이면 복사 시 명령이 깨짐)
5. 코드 블록 언어 라벨 누락
6. 옮기는 과정에서 생긴 새 오타

## 합친 뒤 통일 점검

- 섹션을 합친 원고로 `scripts/check_structure.py`와 `scripts/lint_prose.py`를 다시 실행한다. 캡션 번호 연속성과 섹션 번호 참조는 섹션을 합칠 때 가장 자주 깨진다
- 같은 개념을 저자마다 다르게 부르는지 확인한다(예: 한쪽은 "AgentCore Runtime", 다른 쪽은 "런타임"). 다르면 style.md 기준으로 맞추고, 상대 섹션이면 코멘트로 전달한다
- 게시 채널이 요구하는 포맷(예: WordPress HTML) 변환과 최종 품질 리뷰는 별도 패스로 진행한다

**완료 기준**: 공동 저자 피드백이 원고에 반영되고, 협업 도구로 옮긴 경우 여섯 가지 오류가 문서 전체에서 점검됨.
