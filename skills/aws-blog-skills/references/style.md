# 문장·표기 규칙

문장을 쓰거나 고칠 때 항상 적용한다. `scripts/lint_prose.py`가 금지어를 기계적으로 잡지만, 표기 규칙은 쓰는 순간 지켜야 한다.

## 금지어와 대체 표현

| 금지 | 대체 | 비고 |
|---|---|---|
| 레버 | 해법 | 본문, 표, 다이어그램 라벨 모두 |
| 돌다, 돌리다 (잡·봇 실행 의미) | 실행되다, 실행하다 | |
| 가운뎃점(·) | 본문과 표는 쉼표나 "와", "과", "및". 다이어그램 텍스트만 슬래시 | 본문·표·다이어그램 텍스트 전부. 일반 문장의 슬래시 금지 규칙과 맞춤 (2026-11-01 정리) |
| em dash(—), en dash(–) | 하이픈, 쉼표, 괄호, 문장 분리 | 제목의 en dash는 허용 |
| 쓰다, 씁니다, 쓸 수 (사용 의미) | 사용하다, 사용합니다 | |
| 낭비 절감 | 비용 절감 | |
| 붙는다, 붙습니다 (과금 의미) | 과금됩니다, 부과됩니다, 발생합니다 | |
| 암시적 캐싱 | 묵시적 캐싱(Implicit Prompt Caching) | |
| 미국 본토 리전 | 미국 리전 | Contiguous United States 번역 시 (2026-09-18 확정) |
| ~하세요 (권고) | ~하는 것을 권고합니다 / 권고드립니다 | 이전 규칙 "권고합니다 → ~세요"는 폐기 |
| 문서가 짚는 부분입니다 / 문서가 안내합니다 (문장 끝) | 직접 서술 | 출처 표시는 문단당 "문서에 따르면" 1회로 충분 |
| 다음과 같습니다 / 크게 세 가지로 | 도입구 없이 바로 서술 | |
| 저(저자 지칭) | 필자 | |

## 용어 표기

- 기술 용어는 첫 등장 시 "한국어 또는 영어 원어(괄호 보충)" 병기, 이후 한 가지만. 확정 형태: "정액 요금제(Flat-rate pricing)", "포트페어(Port-pair)", "데이터 전송 아웃(DTO)", "사용 가능 용량(Effective bandwidth)", "Resiliency Group(복원력 그룹)", "Prefix(요청의 앞부분)", "콜드 스타트(캐시가 비어 있음)", "Pathspec(경로 패턴)", "Shallow 체크아웃(커밋 1개만 받는 체크아웃)", "표준 입력(stdin)", "잡(Job)", "묵시적 캐싱(Implicit Prompt Caching)"
- 리드에서 병기한 용어를 리드 문장 삭제로 잃으면 다음 첫 등장 위치로 병기를 옮긴다
- PrivateLink/VPC Lattice: "소비자(Consumer)", "공급자(Provider)"
- NLB: "AZ 친화도(Zonal Affinity)"
- 컴포넌트는 풀네임 접두어(AgentCore Runtime, Direct Connect Gateway)
- AWS 공식 한국어 용어 우선(전용 연결, 호스팅 연결, 가상 인터페이스, 가상 프라이빗 게이트웨이)
- 기능 이름은 발표 기능명, 문서 페이지명, API 파라미터명의 세 층위를 구분한다. 첫 등장에서 관계를 한 문장으로 잇는다("API 설정에서는 `privateEndpoint` 블록으로 구성합니다"). 기준은 verification.md (2026-11-01 추가)
- 숫자 카운터는 한글로 풀어 쓴다: "세 가지", "두 가지". 단위가 붙는 수치는 아라비아 숫자(10 Gbps, 744시간, 2개)
- 금액: `8,154.24 USD` 본문, 다이어그램에서는 `$8,154.24`. 소수 둘째 자리, 천 단위 쉼표
- 단위 정의는 캡션에: TB = 1,024 GB, GB = 2^30 바이트, 평균 속도 = 월 DTO ÷ 월 시간(기간 평균, 피크 아님)
- 슬래시 풀기: 어느 쪽이든 → "이나", 둘 다 → "와", 나열 → 쉼표. 다이어그램 텍스트 안에서는 슬래시 유지
- 예시 도메인은 RFC 2606 계열, 계정 ID·시크릿은 마스킹

## 문장 원칙

- 한 문장에 한 생각
- 문장 길이: 120자를 넘으면 분리를 검토하고, 140자를 넘으면 반드시 나눈다 (2026-11-01 확정, 이전 100자 기준 대체). 글자 수는 공백 포함, 링크는 표시 텍스트만 센다. 표, 코드 블록, 캡션, 참고 자료 목록, 저자 소개는 제외. `lint_prose.py`가 120자 초과를 경고, 140자 초과를 HARD로 잡는다
- 나누는 방법: 연결어미(-고, -며, -지만, -는데, -면서)에서 끊고 두 번째 문장의 주어를 되살린다. 조건과 결과가 한 문장에 겹치면 조건을 앞 문장으로 뺀다. 나열이 길어 넘친 문장은 항목을 두 문장으로 나누거나, 비교할 값이면 표로 옮긴다. 나눈 뒤에도 내용 앵커(수치, 고유명사, 조건)는 그대로 남긴다
- 압축·번역투 구문보다 풀어 쓴 한국어: "두 값이 같아지는 DTO 양은 다음 식으로 구합니다"처럼 주어와 동사를 분명히
- 원리 → 영향 → 행동. 추상 규칙에는 구체 수치(376 Mbps, 5%)나 명령 예시를 짝지운다
- 표 도입 문장은 표에 없는 정보만. 표 뒤에는 해석: 가장 중요한 숫자 하나를 문장으로 다시 말하고 의미를 붙인다
- 두 구성을 비교할 때 결론을 한 문장으로: "두 구성의 차이는 요금이 아니라 용량입니다"
- 사용자 교정 "X → Y"는 정확히 적용하고 같은 패턴을 전수 스윕. 세 번 반복되면 이 표에 등록

## 출처 서술

- 사실 문장은 직접 서술. 문단에 출처 표시가 필요하면 "Pricing Guide에 따르면", "User Guide에 따르면"을 문단당 1회
- 공식 문서끼리 다르면 "A 문서는 X로, B 문서는 Y로 안내합니다"로 병기하고 "계정 담당자를 통해 확인하는 것을 권고합니다"로 닫는다. 한쪽을 임의로 택하지 않는다
- 공개 단가 예시(요금 페이지의 특정 로케이션 단가)를 다른 로케이션에 대입하면 표 캡션에 "로케이션별 단가는 요금 페이지에서 재확인이 필요합니다"를 적는다
- 고객 자료(PDF)와 공식 문서가 다르면 공식 문서를 따르고 차이를 사용자에게 보고한다
- 계산 결과는 "추정치", "예상됩니다"로 쓰고, 말미 고지에 기준일과 전제를 적는다

## 볼드와 장식

- 본문 볼드는 저자 소개의 이름 외에는 거의 쓰지 않는다. 헤딩과 표가 강조 역할을 한다
- 이모지, 따옴표 강조, 불릿 남발 금지. 전환 절차처럼 순서가 의미 있는 곳만 번호 목록
