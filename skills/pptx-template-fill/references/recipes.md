## 1. 표지와 제목 - run 분할

표지 제목은 색을 두 가지로 나누려고 한 문단을 여러 run 으로 쪼갠 경우가 많다.
인벤토리의 `RUNS=['First Half ', 'Business Performance Report']` 가 그 신호다.
run 하나씩 대응시키면 원본의 색 대비가 그대로 유지된다.

```python
T.apply_runs(S[0], [
    ('First Half', 'AWS WADD '),                    # 강조색 run
    ('Business Performance Report', '진단 결과 보고'),  # 기본색 run
])
```

전체 문장으로 지정하면 폴백 경로를 타서 첫 run 색으로 통일된다. 색 구분을 살릴지
없앨지에 따라 선택한다.

날짜/기간처럼 `'January ', '– ', 'June', '20XX '` 로 4분할된 상자는 첫 run 에 전체
문자열을 넣고 나머지를 비우는 편이 깔끔하다.

```python
T.apply_runs(S[0], [('January', '2026.04 - 2026.07'), ('– ', ''), ('June', ''), ('20XX', '최근 30일 기준')])
```

## 2. 스탯 카드 세트

스탯 카드는 보통 값 / 라벨 / 증감 3개 텍스트 상자가 한 세트다. 셋을 함께 바꿔야
의미가 맞는다. 값만 바꾸고 `+ 12.4% YoY` 를 남기면 곧바로 오류로 읽힌다.

```python
T.apply_runs(s, [
    ('84.7 B', '$54.5K'), ('First half sales', 'WebConnect 월 비용'), ('+ 12.4% YoY', '실질 $50.7K'),
    ('10.4 B', '$19K~32K'), ('net profit', '월 절감 잠재'),          ('+ 18.7% YoY', '37~61%'),
])
```

값이 길어지면(`$19K~32K` 처럼) 카드 폭을 넘길 수 있다. 카드는 폭이 고정이므로
폰트를 줄이기보다 표기를 줄인다(`$19~32K`). QA 렌더에서 화면 밖 텍스트로 잡힌다.

## 3. 표 - 행 수 맞추기

행 수가 상한이다. 항목이 더 많으면 묶고, 적으면 행을 삭제한다.

```python
T.fill_table(s, 21, [
    ['우선순위', '개선 과제', '규모', '기대 효과', '시기', '상태'],   # 헤더도 함께
    ['P0', 'svclogs 디스크 안정화', '여유 16GiB', '안정성 확보', '즉시', '● 착수'],
])
T.drop_last_rows(s, 21, 2)   # 남는 2행 삭제
```

셀 안에서 줄을 나눠야 하면 `'오너 : CPE\n조치 : 완료'`. 셀은 기본이 병합
(`grow=False`)이라 행 높이가 늘지 않는다. 반드시 두 줄로 보이게 하려면
`set_cell(cell, text, grow=True)` 를 쓰되 표 전체가 아래로 밀리는지 확인한다.

헤더 행에 병합 셀이 있으면 `fill_table` 의 matrix 에서 병합된 위치는 `None` 으로
두고 대표 셀에만 값을 넣는다.

## 4. 파이 차트 + 별도 범례 표

템플릿의 파이 범례는 차트 범례가 아니라 옆에 놓인 작은 표인 경우가 흔하다. 둘을
같이 고쳐야 하고, 항목 수가 줄면 표 행도 지운다.

```python
T.chart_replace(s, 29, ['OpenSearch', 'EC2', 'RDS', 'MSK'], [('비중', [34.6, 16.0, 21.3, 28.1])])
T.fill_table(s, 30, [[None, 'OpenSearch', '34.6%'], [None, 'EC2', '16.0%'],
                     [None, 'RDS', '21.3%'], [None, 'MSK', '28.1%']])
T.drop_last_rows(s, 30, 1)   # 원래 5행이었으면 1행 삭제
```

첫 열이 `None` 인 이유: 그 칸은 색 견본 도형이 들어 있어 텍스트를 넣으면 안 된다.

## 5. 콤보(복합) 차트

`plots` 가 2개 이상이면 막대+영역, 막대+선처럼 두 종류가 겹친 차트다.
`replace_data` 는 이 구조를 하나로 붕괴시키므로 XML 캐시를 직접 덮어쓴다.

```python
T.combo_edit(s, 6,
    cats=['약정', 'Graviton', 'EKS', 'LB', 'OpenSearch', 'DB', 'MSK', '기타'],
    series_vals=[[12.9, 7.5, 3.0, 3.3, 12.0, 4.4, 1.5, 1.0]],   # 시리즈 순서대로
    series_names=['최대 절감'])                                  # 'DATA','20XX' 제거
```

제약: **데이터 포인트 개수가 원본과 같아야 한다**. 캐시된 `c:pt` 를 덮어쓰는
방식이라 개수를 늘릴 수 없다. 항목이 더 필요하면 카테고리 수가 맞는 다른
슬라이드의 차트를 재활용하거나, 표현할 항목을 템플릿 개수로 묶는다.

`series_names` 를 빼먹으면 범례에 `DATA`, `20XX` 같은 템플릿 문구가 남는다.
QA 의 `--tokens` 에 이 값들을 꼭 넣어 둔다.

## 6. 축 스케일 고정 해제

템플릿 차트는 원본 수치에 맞춰 축 최대/최소가 박혀 있을 수 있다. 새 데이터의
크기가 다르면 막대가 잘리거나 바닥에 눌린다.

```python
T.clear_axis_scale(chart)          # chart_replace/combo_edit 은 기본 호출
T.clear_axis_scale(chart, axes=('c:valAx', 'c:catAx'))
```

해제 후에는 PowerPoint 가 눈금 간격을 다시 계산하므로, QA 렌더에서 축 숫자가
바뀌었다는 경고가 뜨는 것이 정상이다.

## 7. 진행률 바

트랙(회색 배경)과 필(강조색) 2겹 도형이다. 인벤토리에서 같은 `x`/`y` 에 폭만
다른 도형 쌍을 찾으면 된다.

```
id 28 x=5.68 y=2.45 w=4.47   <- 트랙
id 29 x=5.68 y=2.45 w=2.21   <- 필 (52%)
```

```python
T.set_bar_fraction(s, 28, 29, 0.85)   # 라벨 '85%' 와 함께 바꿀 것
```

상태 칩(`Normal`/`Delay`)의 배경색은 테마색으로 지정된 경우가 많아 색까지 바꾸려면
`fill.fore_color` 를 별도로 손대야 한다. 텍스트만으로 의미가 전달되면 색은 원본을
두는 편이 안전하다.

## 8. 간트 / 로드맵 타임라인

표 격자 + 갈매기형 바 + Today 세로선 조합이 흔하다. 헤더 월 라벨을 바꾸면 바
위치도 새 기간에 맞춰 옮겨야 한다.

```python
col0, colw = T.table_grid(s, 6, first_data_col=1)     # 첫 데이터 열의 x, 열 폭
T.place_span(s, 10, col0, colw, start_index=0, span=3, inset=T.emu(0.02))  # 8~10월
T.place_span(s, 23, col0, colw, start_index=2, span=4)                     # 10~1월
T.move_resize(s, 21, left=col0 + colw * 0)            # Today 세로선
T.move_resize(s, 19, left=col0 + colw * 0 - T.emu(0.5))  # 'Today' 라벨
```

`start_index` 는 0-based 열 번호, `span` 은 걸치는 열 수. `inset` 은 셀 경계선과
붙지 않게 좌우로 살짝 띄운다.

## 9. 인물 사진을 로고로 교체

그림 placeholder 는 이미지 소스를 교체할 수 없다. 영역을 기억해 지우고 새로
넣는다. 로고는 비율 유지가 중요하므로 `contain`.

```python
T.swap_picture(s, 12, 'company_logo.png', mode='contain', pad=0.1)
```

`mode='fill'` 은 영역을 꽉 채우지만 비율이 왜곡되므로 배경 사진에만 쓴다.
로고 여백이 답답하면 `pad` 를 0.05~0.2 로 조절한다.

원본 사진 위에 텍스트가 얹혀 있던 자리라면, 사진을 지운 뒤 그 텍스트가 배경 없이
떠 보일 수 있다. 그때는 사진을 지우지 않고 로고를 별도 위치에 배치하는 편이 낫다.

## 10. 발표 노트 줄바꿈

python-pptx 로 `tf.text = 'A\nB'` 를 넣으면 문단 2개(`<a:p>`)가 되어 PowerPoint 에서
실제 줄바꿈으로 보인다. 한 문장당 한 줄이 발표 중 읽기 좋다.

```python
T.set_notes(s, '비용 총괄입니다.\nPayer 전체는 월 35만 4천 달러입니다.\nMSK 증설에도 총량은 안정적입니다.')
```

노트 마스터에 body placeholder 가 없어 `notes_text_frame` 이 `None` 인 템플릿이
있다. `donor=S[0]` 로 placeholder 를 복제한다.

pptxgenjs 로 만든 덱은 사정이 다르다. `addNotes` 는 `\n` 을 단일 run 안의 문자로
넣어 줄바꿈으로 렌더링되지 않는다. 그 경우 저장 후 각
`ppt/notesSlides/notesSlideN.xml` 에서 문장 사이 개행을 OOXML 줄바꿈으로 바꾼다.

```
정규식: (?<!>)(\r\n|\r|\n)(?!<)
치환  : </a:t></a:r><a:br/><a:r><a:t>
```

QA 는 문단 2개 이상 또는 `<a:br/>` 존재로 이를 판정한다.

## 11. 슬라이드 장수 조정

템플릿이 필요보다 많으면 빈 슬라이드로 남기지 말고 지운다.

```python
T.keep_slides(prs, list(range(0, 24)))   # 앞 24장만 유지
T.delete_slide(prs, 29)                  # 여러 장은 큰 인덱스부터
T.move_slide(prs, 29, 3)                 # 클로징을 앞으로 옮길 때
```

같은 레이아웃이 더 필요하면 python-pptx 에는 슬라이드 복제 API 가 없다. 이때는
(1) 템플릿에서 같은 레이아웃을 쓰는 다른 슬라이드를 찾아 쓰거나 (2) 콘텐츠를
기존 장수에 맞춰 압축한다. 굳이 복제하려면 `copy.deepcopy(slide._element)` 후
관계(rels)를 수동으로 복사해야 하는데, 이미지/차트 참조가 많으면 깨지기 쉽다.

## 12. 그룹 안쪽 도형

카드/배지가 그룹으로 묶여 있으면 `slide.shapes` 순회로는 안쪽 텍스트가 안 잡힌다.
`apply_runs` 와 `shape_by_id` 는 그룹 내부까지 재귀하지만, 그룹 안 도형의 좌표는
그룹 변환에 따라 인벤토리 표시값과 실제 렌더 위치가 다를 수 있다.

그룹 안 도형의 위치를 옮겨야 하면, 개별 도형이 아니라 **그룹 자체**를
`move_resize` 하는 편이 예측 가능하다.

## 13. 폰트 미설치 환경 렌더 QA

대상 폰트가 컨테이너에 없으면 LibreOffice 가 임의 대체 폰트로 렌더하므로 폭이
달라져 오버플로 판정이 흐려진다. fontconfig 별칭으로 유사 폰트에 매핑해 근사도를
높인다.

```bash
mkdir -p ~/.config/fontconfig && cat > ~/.config/fontconfig/fonts.conf << 'EOF'
<?xml version="1.0"?>
<!DOCTYPE fontconfig SYSTEM "fonts.dtd">
<fontconfig>
  <match target="pattern">
    <test name="family"><string>나눔스퀘어OTF Bold</string></test>
    <edit name="family" mode="prepend" binding="strong"><string>Noto Sans CJK KR</string></edit>
    <edit name="weight" mode="assign"><const>bold</const></edit>
  </match>
</fontconfig>
EOF
fc-cache -f && fc-match "나눔스퀘어OTF Bold"
```

나눔스퀘어는 Noto Sans CJK 보다 폭이 좁은 편이라 이 근사는 보수적으로(오버플로를
과다 보고하는 쪽으로) 기운다. 결과를 전달할 때 근사임을 밝히고, 밀도 높은 표
슬라이드는 사용자가 PowerPoint 에서 확인하도록 안내한다.

## 14. 슬라이드 재목적화 판단

템플릿 슬라이드의 원래 용도를 그대로 쓸 필요는 없다. 레이아웃 구조가 맞으면
용도를 바꿔 쓰는 것이 템플릿-필의 핵심 기술이다.

| 템플릿 원래 용도 | 구조 | 재목적화 예 |
|---|---|---|
| CEO 메시지 (인용 + 사진) | 큰 인용문 + 3문단 + 서명 | 진단 총평, 심사 의견, 프로젝트 회고 |
| 손익계산서 (9행 x 5열) | 계정/전기/당기/증감/증감률 | Before → After 비교, 구성 변경 내역 |
| 부서별 성과 (스탯 4 + 차트 2) | 지표 카드 + 추이 + 구성비 | 도메인별 진단, 서비스별 분석 |
| KPI 달성 표 (13행 x 6열) | 분류/지표/목표/실적/증감/상태 | 개선 과제 목록, 리스크 등록부 |
| 프로젝트 현황 (진행률 5행) | 이름 + 메타 + 바 + 상태 칩 | 이행 현황, 마이그레이션 진행 |
| 반기 목표 (4카드 + 빅넘버) | 목표 카드 + 큰 수치 + 비교 차트 | 6개월 목표, 절감 목표 |

판단 기준은 **구조 일치**다. "13행 6열 표" 는 무엇이든 담을 수 있지만, 6열의
의미가 자연스럽게 매핑되지 않으면 무리해서 쓰지 말고 다른 슬라이드를 찾는다.
매핑 표(Step 2)를 사용자에게 확인받는 이유가 여기에 있다.
