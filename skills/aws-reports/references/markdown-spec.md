# 원고 Markdown 규칙

`scripts/report.mjs`가 읽는 Markdown 형식이다. 벤치마크 보고서와 PoC 결과 보고서가 같은 형식을 쓴다. 일반 GFM에 몇 가지 약속만 더했다. Word와 HTML은 이 원고 하나에서 함께 만들어지므로, 두 결과물의 내용과 번호는 항상 같다.

## 머리말 (front matter)

```markdown
---
title: Graviton과 Intel 인스턴스의 Spring Boot 성능 비교
eyebrow: Amazon EKS, Karpenter, Spring Boot 벤치마크
meta: 측정일 2026년 11월 2일, 서울 리전(ap-northeast-2)
header: Graviton과 Intel 인스턴스의 Spring Boot 성능 비교
description: 한 줄 요약 (HTML meta description, Word 문서 속성)
author: 작성자 이름 (Word 문서 속성, 생략 가능)
numbered: true
---
```

| 키 | 쓰임 | 생략하면 |
|---|---|---|
| `title` | Word 제목, HTML `<h1>`과 `<title>` | 첫 `# 제목` 줄, 그것도 없으면 파일 이름 |
| `eyebrow` | 제목 위 작은 회색 분류 문구 | 표시하지 않음 |
| `meta` | 제목 아래 측정일, 리전 같은 한 줄 | 표시하지 않음 |
| `header` | Word 머리글, HTML 인쇄 머리글 | `title` |
| `numbered` | `## 섹션`에 `1.`, `2.` 번호 | `true` |

머리말 값은 한 줄 문자열만 쓴다(YAML 목록, 여러 줄 값은 읽지 않는다).

## 리드와 결론 문단

첫 `##` 앞의 문단이 리드다. 무엇을, 왜, 어떤 조건으로 비교했는지 쓴다. 문단 전체를 `**...**`로 감싸면 굵은 결론 문단이 된다. 핵심 결과 표도 첫 `##` 앞에 둔다.

## 섹션

- `## 제목`은 번호 붙은 큰 제목(Word Heading 1), `### 제목`은 번호 없는 소제목(Heading 2)이다. `####` 이하는 `###`로 내린다.
- `## 측정 환경과 방법 {#method}`처럼 끝에 `{#id}`를 붙이면 그 id로 책갈피(Word)와 앵커(HTML)가 생긴다. 본문에서 `[측정 조건](#method)`로 연결한다. 생략하면 `sec-1`, `sec-2`가 붙는다.
- `<!-- pagebreak -->`만 있는 줄 다음 블록은 새 페이지에서 시작한다(Word는 페이지 나눔, HTML은 인쇄할 때). 보통 첫 결과 섹션 앞과 종합 평가 앞에 둔다.

## 그림

이미지 하나만 있는 문단이 그림이다. 대체 텍스트가 캡션이 되고, 아래에 `그림 N.`이 자동으로 붙는다.

```markdown
![인스턴스별 종합 처리량 지수 (요청/초)](charts/chart-score.png "width=16")

주: 점은 회차별 값, 막대는 중앙값입니다.
```

- `"width=14"`는 그림 폭(cm)이다. 기본 16 cm, 최대 17 cm(본문 폭)다. 작은 차트는 13~14 cm.
- 경로는 원고 파일 기준 상대 경로다. PNG나 JPEG만 쓴다. SVG는 `scripts/svg2png.py`로 PNG를 만든 뒤 넣는다.
- 캡션을 대체 텍스트와 다르게 쓰고 싶으면 바로 다음 문단을 `그림: 캡션`으로 쓴다.
- 캡션 다음 문단이 `주:`로 시작하면 캡션 아래 작은 회색 설명이 된다. `주:`라는 글자는 출력에서 지워진다.
- 주석이 한 줄에 들어가면(한글만 쓰면 약 58자) 가운데, 두 줄 이상이면 왼쪽 정렬된다. 사용자가 Word에서 직접 그렇게 고쳤다. 가운데 정렬로 보이게 하려면 주석을 한 줄로 줄인다.
- `그림 1`처럼 번호를 원고에 직접 쓰지 않는다. 번호는 빌드할 때 매긴다.

## 표

GFM 표를 쓰고, 빈 줄 하나를 둔 다음 `표: 캡션` 문단을 쓴다. 캡션은 표 아래에 `표 N.`과 함께 들어간다.

```markdown
| 인스턴스 | 프로세서 | 요청/초 | p99 (ms) |
|---|---|---:|---:|
| c8g.2xlarge | Graviton4 | 13,890 | 12.4 |
| c8i.2xlarge | Granite Rapids | 15,210 | 10.9 |

표: 인스턴스별 최대 처리량 (C2 전용 프로파일)

주: 엔드포인트마다 최대 처리량을 낸 커넥션 단계의 값입니다.
```

- 빈 줄 없이 바로 `표:`를 쓰면 GFM이 그 줄을 표의 마지막 행으로 읽는다. 변환기가 이 경우도 캡션으로 되돌리지만, 빈 줄을 두는 것이 안전하다.
- 정렬: `---:`는 오른쪽, `:---:`는 가운데. 정렬을 지정하지 않으면 첫 열은 왼쪽, 숫자가 60% 이상인 열은 오른쪽이다.
- 숫자는 천 단위 쉼표와 단위를 셀 안에 함께 쓴다(`13,890`, `0.85배`, `+63.2%`, `$0.4352`). 값이 없으면 `—`.
- 열 폭은 글자 수로 자동 계산한다(한글 1.75배).
- 글자 크기는 열 수로 정한다: 7열까지 8pt, 8~9열은 머리글 7.5pt·본문 7pt, 10열 이상은 6.5pt. 10열이 넘으면 표를 둘로 나누는 것을 먼저 검토한다.
- 머리글이 열 폭에 한 줄로 들어가지 않으면 끝의 단위나 괄호를 둘째 줄로 내리고(`On-Demand (USD/시간)` → `On-Demand` / `(USD/시간)`), 그 표의 머리글 셀을 모두 가운데 정렬한다. 머리글이 모두 한 줄에 들어가는 표는 열 정렬(숫자 열은 오른쪽)을 그대로 쓴다. 사용자가 Word에서 직접 고친 규칙이다.
- 단위 괄호가 없는 긴 머리글은 원하는 자리에 `<br>`을 넣어 직접 나눈다: `| JVM 사용<br>코어 |`. 나눈 머리글이 하나라도 있으면 그 표의 머리글은 가운데 정렬된다.
- 머리글 셀에도 `` `코드` ``를 쓸 수 있고 D2Coding으로 나온다.

## 박스 (안내, 주의, 권고)

인용문(`>`)이 회색 배경과 가는 테두리의 박스가 된다. 첫 문단 전체가 굵게면 박스 제목이다. 왼쪽 강조 막대는 없다.

```markdown
> **벤치마크 노드: 필수 DaemonSet만 유지**
>
> 관측 에이전트 `telemetry-beyla`는 모든 taint를 허용하므로 nodeAffinity로 제외했습니다.
>
> - 남은 DaemonSet: aws-node, kube-proxy, eks-pod-identity-agent
```

- 박스 제목은 문장이 아니라 함축형으로 쓴다: "벤치마크 노드: 필수 DaemonSet만 유지", "첫 측정 폐기: Tomcat keep-alive 기본값", "권고". 독자가 고객이므로 "고객 권고"라고 쓰지 않는다. "~했습니다"로 끝나면 변환기와 검사 스크립트가 경고한다.
- 박스 안에는 문단, 목록, 코드 블록을 쓸 수 있다. 표와 그림은 박스 밖에 둔다.
- GitHub 알림 문법(`> [!NOTE]`)의 표식은 지우고 같은 박스로 만든다.

## 코드

- 인라인 `` `podAntiAffinity` ``는 D2Coding 글꼴이 된다(Word는 영문/기호 부분집합을 문서에 포함). 명령, 설정 키, 클래스 이름, 경로, JVM 옵션, 리소스 이름은 모두 인라인 코드로 쓴다.
- ```` ``` ```` 코드 블록은 옅은 회색 상자에 D2Coding으로 들어간다. 탭은 공백 4칸으로 바뀐다. 줄이 길면 HTML은 가로 스크롤, Word는 줄바꿈된다.

## 목록, 강조, 링크

- `-` 목록, `1.` 번호 목록, 두 단계까지 중첩.
- `**굵게**`, `*기울임*`, `~~취소선~~`.
- `[문서 이름](https://...)`은 외부 링크, `[텍스트](#id)`는 문서 안 링크.
- 줄바꿈 한 번은 공백으로 이어지고, 빈 줄이 문단을 나눈다.

## 지원하지 않는 것

원시 HTML 블록(주석 제외), `<br>` 말고 다른 인라인 HTML, 각주, 수평선(`---`, 경고 후 무시), 문단 안의 이미지, 표 셀 병합. 필요하면 표를 나누거나 문단으로 풀어 쓴다.
