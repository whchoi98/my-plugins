# 문체와 표기 규칙

보고서를 쓰면서 사용자가 직접 교정한 표현과, 그 교정에서 드러난 원칙이다. 벤치마크와 PoC 보고서가 함께 따른다. 검사 스크립트(`scripts/check_report.py`)는 `scripts/style_terms.json`의 표현을 찾아 경고한다. 새 교정을 받으면 두 파일에 함께 추가한다. 한 유형에만 해당하는 표현은 `style_terms.json`에 `"profiles": ["poc"]`처럼 프로필을 붙인다.

## 기본 문체

- AWS 기술 블로그의 격식체("~습니다")로 쓴다. 측정한 사실을 먼저, 해석은 그다음에 쓴다.
- 문장은 120자 안쪽, 한 문단은 한 가지 주장으로 3~4문장. 같은 숫자를 본문, 표, 캡션에 세 번 반복하지 않는다. 본문은 숫자가 말하는 의미를, 표는 숫자를 맡는다.
- AI 티 나는 표현을 빼고 양을 줄인다: "다양한", "효과적인", "핵심적인", "~를 통해", "~에 있어", "결론적으로", "주목할 만한", 의미 없는 요약 문장, 문단마다 붙는 접속사. 같은 플러그인의 `../aws-blog-skills/scripts/lint_prose.py`로 HARD 0을 확인한다.
- 측정값과 추정을 구분한다. 측정하지 않은 것은 "측정하지 않았습니다" 또는 "이번 측정 범위 밖"으로 쓴다.

## 사용자가 교정한 표현

| 쓰지 않는 표현 | 대신 쓰는 표현 | 이유 |
|---|---|---|
| 쌍 (여덟 쌍, 노드 쌍) | 페어 (8개 페어, 노드 페어) | 서버 노드와 부하 발생기 노드의 묶음을 엔지니어들이 부르는 말이다 |
| 잠금, 잠금 경합 | 락(lock), 락 경합 | 첫 등장에 `락(lock)`으로 병기하고 그다음은 "락" |
| 직렬화 (락 대기를 가리킬 때) | 락이 걸린 구간을 한 번에 한 스레드씩 지나간다 | 직렬화는 serialization(객체 변환)으로 읽혀 어색하다 |
| 수의사 목록 | Vet 목록 | 애플리케이션의 도메인 엔터티(Owner, Pet, Visit, Vet)는 번역하지 않는다 |
| 박스 제목을 문장으로: "노드에는 필수 DaemonSet만 남겼습니다" | 함축형: "벤치마크 노드: 필수 DaemonSet만 유지" | 박스 제목은 훑어 읽는 표지다 |
| "같은 내용의 대화형 대시보드: URL", "출처 패널에서 내려받을 수 있습니다" | (삭제) | Word와 HTML 보고서는 그 자체로 완결된 문서다. 다른 화면의 UI를 가리키지 않는다 |
| "3.1절의", "4장에서" | "앞에서 본 측정 조건", "뒤에서 설명할 원인 분석" | 섹션 순서를 바꾸면 번호 참조가 조용히 틀린다(이번에도 측정 방법 섹션을 맨 앞으로 옮겼다) |
| 앞서 | 앞에서 | AWS 블로그 금지어 |
| 박스 제목 "고객 권고" | "권고" | 보고서를 읽는 사람이 고객이다. 고객에게 "고객 권고"라고 쓰지 않는다 |

같은 패턴이 문서 다른 곳에 남지 않도록 교정을 받으면 문서 전체를 다시 찾는다(그림 안의 글자, 표 항목 이름, 차트 라벨 포함).

## 표기

- 제품과 서비스 이름은 영문 원문: Amazon EKS, Karpenter, AWS Graviton4, Intel Xeon 6, Amazon Corretto 21, Spring Boot 3.5.
- 인스턴스 타입은 소문자 그대로, 코드 서식 없이: c8g.2xlarge, m7i.2xlarge.
- 명령, 설정 키, JVM 옵션, 클래스 이름, 경로, Kubernetes 리소스 이름은 인라인 코드(D2Coding): `-XX:-TieredCompilation`, `podAntiAffinity`, `UrlJarFiles$Cache`, `/proc/stat`.
- 숫자: 천 단위 쉼표(13,890), 비율은 "0.85배", 변화율은 부호와 함께 "+63.2%", "−5%". 가격은 "$0.4352/시간"처럼 단위와 기준(서울 리전 On-Demand)을 쓴다.
- 기준이 있는 비교는 기준을 밝힌다: "c7i.2xlarge 대비", "c8i.2xlarge 가격의 0.85배".
- 영어 개념어를 직역한 "계약"(contract), "축"(axis)은 쓰지 않는다.

## 권고 박스

- 박스 제목은 "권고"다. 항목은 4~6개, 각 항목은 "조건 → 선택 → 확인할 것" 순서로 한 문장 또는 두 문장. 예: "c8g.2xlarge는 요청 처리 대부분이 CPU 집약적인 로직일 때 대안이 됩니다. 실제 요청 구성으로 측정하고, 스레드 덤프로 락 경합이 없는지 확인한 뒤 결정합니다."
- 측정의 한계(단일 AZ, 단일 리전, On-Demand 가격, 측정 기간)는 권고에 섞지 않고 결과 해석 박스에 모아 둔다.
- 결론 쓰는 법은 보고서 종류마다 다르다. 벤치마크는 `benchmark-structure.md`, PoC는 `poc-verdict-rules.md`를 본다.
