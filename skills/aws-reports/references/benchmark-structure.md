# 벤치마크 보고서 구성

독자는 고객과 동료 엔지니어다. 이들은 "측정 조건을 믿을 수 있는가"를 먼저 확인하고, 마지막에 "그래서 무엇을 고르나"를 찾는다. 그래서 측정 환경과 방법이 결과보다 앞에, 종합 평가가 맨 끝에 온다. 사용자는 실제로 측정 방법 섹션을 9번째에서 첫 번째로 옮기게 했고, 종합 평가는 마지막에 두라고 했다.

## 순서

```
[머리말] eyebrow · 제목 · meta(측정일, 리전)
[리드]   무엇을, 왜, 어떤 조건으로 비교했는지 2~3문장
[결론]   **굵은 한 문단**: 독자의 질문에 대한 답과 그 조건
[표 1]   핵심 결과 (항목 | 결과 | 비고) 4~6행

## 1. 측정 환경과 방법          ← 항상 첫 섹션
   그림: 테스트 구성도 (AWS 아이콘 아키텍처, SVG → PNG)
   본문: 노드 배치, 격리 방법, 회차 구성
   박스: 벤치마크 노드: 필수 DaemonSet만 유지 / 첫 측정 폐기: <원인>
   표: 측정 대상 (인스턴스 | 프로세서 | vCPU | 메모리 | 시간당 가격)
   표: 측정 조건 (항목 | 값)   표: 측정 신뢰도 (변동계수 등)

<!-- pagebreak -->
## 2. 종합 결과                  (가장 중요한 지표 하나: 차트 + 한 문단)
## 3~. 시나리오별 결과           (실제 애플리케이션, 엔드포인트별, 부하 단계별)
##    가격 대비 성능             (성능 ÷ 시간당 가격, 기준 인스턴스 = 1.00)
##    세대 간 향상               (dumbbell 차트, 변화율)
##    설정의 영향                (JVM 프로파일, 런타임 옵션, 콜드 스타트)
##    원인 분석                  (호스트 클럭, 스레드 덤프, 프로파일링 근거)
##    전체 측정값                (부록 성격의 큰 표)

<!-- pagebreak -->
## N. 종합 평가                  ← 항상 마지막 섹션
   본문: 결정 질문에 대한 답
   그림: 시나리오별 비율 (verdict 차트, 기준선 1.0, ±5% 띠)
   표: 시나리오 | 비교 대상 | 비율 | 판정
   박스: 결과를 해석할 때 유의할 점
   박스: 권고 (4~6개 항목)
```

성공 기준을 놓고 충족 여부를 판정하는 PoC 결과 보고서는 `poc-structure.md`의 뼈대(개요 → 성공 기준 → 구성과 방법 → 기준별 결과 → 이슈와 조치 → 비용 → 종합 평가와 다음 단계)를 쓴다. 마이그레이션 검토처럼 판정 기준이 없는 기술 보고서는 이 뼈대를 쓴다: 조건 → 결과 → 원인 → 판단과 권고. 섹션 이름은 내용에 맞게 바꾸되 첫 섹션은 조건, 마지막 섹션은 판단으로 둔다.

## 섹션 하나의 모양

1. 한 문단: 이 섹션이 답하는 질문과 결과 한 줄(숫자 하나나 둘).
2. 그림 또는 표 한두 개, 캡션 아래에 `주:`로 단위와 전제.
3. 한두 문단: 결과를 만든 원인과 예외. 숫자는 표에 맡기고 의미를 쓴다.
4. 필요하면 박스 하나(주의할 점, 폐기한 측정, 조건).

## 차트 고르기 (`scripts/chart_style.py`)

| 보여 줄 것 | 함수 | 메모 |
|---|---|---|
| 인스턴스별 한 지표 순위 | `hbar` | 큰 값부터, 회차 값은 `dots` |
| 기준 대비 비율 (가격 대비 성능) | `hbar(..., ref=1.0)` | 기준 인스턴스를 캡션에 |
| 두 설정 비교 (C2 전용 vs 기본값) | `grouped_hbar` | 둘째 계열은 `MUTED` 회색 |
| 세대 간 변화 | `dumbbell` | 빈 원 = 이전 세대, 찬 원 = 새 세대 |
| 부하 단계별 곡선 | `lines` | c/m 패밀리는 마커, 이전 세대는 점선 |
| 종합 판정 | `verdict` | ±5% 띠는 "비슷" |

색: Graviton 주황 `#E07B2E`, Intel 파랑 `#2F6DB5`, AMD 초록 `#2E9E6B`, 이전 세대는 같은 색 50%. 범례는 차트 위. 그림 폭은 16 cm(작은 차트 13~14 cm).

## 결론 쓰는 법

- 종합 평가는 독자의 결정 질문("어느 쪽이 가격 대비 성능이 좋은가")에 먼저 답한다. 시나리오마다 비율을 보여 주고, ±5% 안은 "비슷"으로 묶는다.
- 판정 표는 시나리오 | 비교 대상 | 비율 | 판정. 판정 단어는 "Graviton 우위", "Intel 우위", "비슷"처럼 기준과 방향이 보이게 쓰고, 표 아래 `주:`에 판정 기준(±5%)을 적는다.
- 권고 박스와 결과 해석 박스는 공통 규칙(`style-rules.md`의 권고 박스)을 따른다.
